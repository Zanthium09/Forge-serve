# Forge-Serve

Self-hosted, distributed LLM inference gateway for open-weight models — an
OpenAI-compatible streaming API with a continuous-batching engine, API-key
auth, admission control, and Prometheus metrics. Built from scratch; the
model is the commodity, the serving system is the project.

See [FORGE_SERVE_BLUEPRINT.md](FORGE_SERVE_BLUEPRINT.md) for the full spec.

**Status: Phase 2 complete** — continuous batching, benchmarked.
Next: multi-worker routing and failover (Phase 3).

## Quickstart

```bash
make model          # download Qwen2.5-1.5B GGUF (~1.1 GB, once)
docker compose up --build
```

Any OpenAI client works by changing only the base URL:

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key="sk-forge-dev-key")
s = client.chat.completions.create(model="qwen2.5-1.5b", stream=True,
        messages=[{"role": "user", "content": "Count from 1 to 5."}])
for chunk in s:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

## Architecture

```
client ──HTTPS/SSE──▶ gateway (Go)                    ──HTTP/NDJSON──▶ worker (Python)
                      · OpenAI-compatible schema                       · continuous batching
                      · API-key auth (SHA-256)                         · KV-cache slots
                      · SSE relay + cancellation                       · FCFS + bounded queue
                      · admission 429 + Retry-After                    · llama.cpp (low-level)
                      · Prometheus /metrics
                          │                  │
                     Postgres            Redis (Phase 4)
                     tenants, keys       rate-limit buckets
```

Request lifecycle, failure paths, and the decode loop's state machine are
documented in [docs/](docs/); decisions live in [docs/adr/](docs/adr/).

## Benchmarks

Intel Core Ultra 9 185H (16C/22T), 32 GB, Docker Desktop/WSL2, Qwen2.5-1.5B
Q4_K_M, 64-token completions. Numbers generated by
[`benchmarks/run_bench.sh`](benchmarks/run_bench.sh) from the CSVs in
[`benchmarks/raw/`](benchmarks/raw/) — see
[the full report](benchmarks/report.md) for methodology and caveats.

**Aggregate throughput (completion tokens/s):**

| Concurrency | Sequential | Continuous batching | Multiplier |
|---|---|---|---|
| 1 | 29.56 | 21.02 | 0.71× |
| 8 | 3.03 | 36.57 | 12.07× |
| 16 | 1.80 | 29.00 | **16.11×** |

The 16× is honest but composite: batching's own ceiling on this CPU is
**2.5×** (measured in isolation — one `llama_decode` over 16 sequences
costs 250 ms versus 39 ms for one), while the rest comes from sequential
serving *degrading* under concurrency rather than merely serializing. At
concurrency 1 batching is a net loss, which is the expected trade-off.

**Latency and load shedding:**

| Metric | Result |
|---|---|
| TTFT p99, concurrency 8 | 4.3 s |
| TTFT p99, concurrency 16 | 18.5 s |
| Concurrency 50 | 24 served, 656 shed with 429 + `Retry-After`, 0 errors |

## What's interesting in here

- **[`worker/engine.py`](worker/engine.py)** — the batching scheduler:
  admit (FCFS) → one shared decode step → immediate eviction, as an explicit
  state machine with named invariants. Its logic sits behind a backend
  protocol so the full scheduler is unit-tested against a fake model in CI.
- **[`worker/backend_llama.py`](worker/backend_llama.py)** — llama.cpp's
  low-level API: one `llama_batch` per iteration across all sequences,
  per-sequence KV ranges freed on eviction, manual sampling.
- **Cancellation, end to end** — a client disconnect cancels the gateway's
  context, aborts the worker request, and evicts the sequence from the live
  batch at the next iteration boundary (verified: `active_seqs` 1 → 0
  within 2 s).
- **[`loadgen/`](loadgen/)** — open- and closed-loop generator that writes
  per-request TTFT/TPOT rows, so every published number traces to a CSV.

## Development

```bash
make test     # Go unit tests
make lint     # golangci-lint
make bench    # full benchmark matrix (~18 min, local hardware only)
make plots    # regenerate summary.csv and charts
```

CI runs lint and unit tests only — inference benchmarks on shared runners
produce meaningless numbers, so they stay local and hardware-disclosed.
